# 环境搭建与运行时配置（Phase 0 记录）

> 记录 AI 教师系统开发环境的搭建过程与关键配置，便于重建环境或排查问题。
> 最后更新：2026-08-14

## 1. 运行时架构

```
前端 (UniApp H5) ──> 后端 (03-Backend) ──> AgentSkills Runtime (仓颉二进制)
                                              ├── PostgreSQL (uctoo 数据库, RBAC 权限)
                                              └── LLM: Agnes (OpenAI 兼容接口)
```

- **运行时**：`@opencangjie/skills`（SDK 1.0.2），内置 Runtime v0.0.22
- **数据库**：PostgreSQL 17（本地，服务名 `postgresql-x64-17`）
- **LLM**：Agnes `agnes-2.0-flash`（OpenAI 兼容，Base URL `https://apihub.agnes-ai.com/v1`）

## 3. 数据库初始化（PostgreSQL 17）

```powershell
# 1. 设置 postgres 密码（与运行时默认连接串一致）
$env:PGPASSWORD = "postgres"
psql -U postgres -h 127.0.0.1 -p 5432 -c "ALTER USER postgres WITH PASSWORD 'uctoo123';"

# 2. 创建数据库
psql -U postgres -h 127.0.0.1 -p 5432 -c "CREATE DATABASE uctoo;"

# 3. 导入建表脚本
$env:PGPASSWORD = "uctoo123"
psql -U postgres -h 127.0.0.1 -p 5432 -d uctoo -v ON_ERROR_STOP=1 -f uctooDB.sql
```

### 初始数据导入（重要）

`uctoov4InitData.sql` 有两个问题需绕过：

1. **permissions 表外键顺序**：INSERT 依赖父记录，需禁用外键检查：
   - 用 Python 在文件头部注入 `SET session_replication_role = replica;`（勿用 PowerShell 改写，会破坏 UTF-8 编码）
   - 修改版已存为 `06-Tools\uctoov4InitData_nofk.sql`

2. **lang 表结构不匹配**：脚本含 `INSERT INTO lang (..., permission_name, ...)`，但 uctooDB.sql 的 lang 表无此列，导入会中断 —— **lang 数据可跳过**，不影响运行时（关键数据在中断前已导入）。

3. **user_has_roles 脏数据**：脚本内引用不存在的 role_id（863e8a2a...），需手动给 demo 用户关联超级管理员角色：

```powershell
psql -U postgres -h 127.0.0.1 -p 5432 -d uctoo -c "INSERT INTO user_has_roles (id, user_id, role_id, status, creator, created_at, updated_at) VALUES (gen_random_uuid(), '505cf909-5e0e-4dde-b215-74274d2cc548', '2338cf7b-82b7-4cf6-b1ae-6a3ca79d683d', 1, '505cf909-5e0e-4dde-b215-74274d2cc548', now(), now());"
```

### 认证协议（坑）

OpenGauss 驱动只支持 **md5** 认证，PostgreSQL 17 默认 scram-sha-256，必须：

```powershell
# 1. 修改 C:\Program Files\PostgreSQL\17\data\pg_hba.conf
#    host all all 127.0.0.1/32 scram-sha-256  →  md5
#    host all all ::1/128     scram-sha-256  →  md5
# 2. 将密码哈希转为 md5 格式
psql -U postgres -h 127.0.0.1 -p 5432 -c "SET password_encryption = 'md5'; ALTER USER postgres WITH PASSWORD 'uctoo123';"
```

不修改会报：`SqlException: invalid AuthenticationRFC5802 message`。

## 5. JWT 认证（开发用）

所有 `/api/v1/uctoo/*` 接口需 Bearer Token（RBAC）。开发验证可用 Node 自签：

```javascript
// 用 HMAC-SHA256 签 JWT，payload: { user: "<userId>", session: "<sessionId>", iat, exp }
// 密钥: uctoo-v4-secret-key（或 JWT_SECRET）
// 用户: demo 用户 id = 505cf909-5e0e-4dde-b215-74274d2cc548
```

## 8. Windows DLL 依赖（坑）

运行时为 MinGW/仓颉编译，缺 DLL 会崩溃或功能静默失效（AI 路由不注册）。`node_modules` 重装会把手动补的 DLL 全部清掉，**必须重建**。需补入 `release\bin\` 的共 6 个：

| DLL | 作用 | 来源 |
|---|---|---|
| `libgcc_s_seh-1.dll`、`libstdc++-6.dll`、`libwinpthread-1.dll` | GCC 运行时（缺失则以 `0xC0000135` 崩溃或报 loading shared libraries） | Git for Windows 自带 `Git\mingw64\bin` |
| `libssp-0.dll` | GCC 栈保护（libcangjie-runtime.dll 导入表需要；新版 gcc-libs 14+ 已不带） | JuliaBinaryWrappers CompilerSupportLibraries v0.5.4 |
| `libcrypto-3-x64.dll`、`libssl-3-x64.dll` | OpenSSL 3（ORM 的 PG md5 认证；缺失则日志报 `CryptoException: MD5_Init` → **ORM 初始化失败 → AI 路由不注册 → 对话 404**） | PostgreSQL 17 自带 `PostgreSQL\17\bin` |

- **备份**：`06-Tools\runtime-dlls\`（已入库）；`start-dev.bat` 启动时检测 bin/ 缺失即自动恢复（P31/P39）
- 同时被重装清掉的还有 `bin\.env` 的全部用户配置——数据库密码经 `local-config.txt` 自动补写；模型配置已迁移到设置页（第 4 节），不再依赖 .env
